## Critical business-data warning

The system already contains real operational data for **2 active stores**. Each store is an independent tenant. Never merge, normalize, reassign, copy, backfill, or rewrite Brand/Product records between these stores in this mission.

Existing `Brand.normalizedName @unique` currently enforces global uniqueness. This mission must **preserve that existing behavior**. Do not remove or weaken it yet. The ability for two stores to own separate Brands with the same normalized name belongs to a later audited migration/cutover increment.

## Objective

Add nullable Branch ownership capability to `Brand` without changing current runtime behavior or existing data.

Required schema capability only:

```prisma
model Branch {
  brands Brand[]
}

model Brand {
  branchId Int?
  branch   Branch? @relation(fields: [branchId], references: [id])
}
```

Do not specify `onDelete` or `onUpdate` explicitly. Record the actual referential actions generated by Prisma in the final report. Generated behavior is temporary nullable-foundation behavior, not permanent Branch lifecycle policy.

## Exact allowed scope

Only these files may change:

1. `prisma/schema.prisma`
2. One new additive migration directory under `prisma/migrations/`
3. One narrowly targeted migration/schema contract test following the existing convention
4. This Mission Pack only when reconciliation is necessary

No Backend runtime, Frontend, controller, service, repository, route, API, policy, mapper, seed, bootstrap, CI, deploy, ProductTemplate, Candidate, Promotion, Media, ProductTypeBrand, or business-flow files may change.

## Required Prisma changes

### Branch model

Add exactly one reverse relation:

```prisma
brands Brand[]
```

Confirm no existing Brand↔Branch relation with different semantics exists. Do not rename existing Branch fields.

### Brand model

Add:

```prisma
branchId Int?
branch   Branch? @relation(fields: [branchId], references: [id])
```

Add only these non-unique indexes:

```prisma
@@index([branchId])
@@index([branchId, active])
@@index([branchId, normalizedName])
```

### Existing uniqueness must remain unchanged

Keep:

```prisma
normalizedName String @unique
```

Do **not** add `@@unique([branchId, normalizedName])` in this increment. Adding it while the global unique remains would be redundant; removing the global unique would change behavior and requires data audit/backfill work that is explicitly out of scope.

Do not make `branchId` required. Do not add a default. Do not infer ownership from Product, ProductType, ProductTypeBrand, BranchPrice, stock, or transactions.

## Migration semantics

Create exactly one additive migration that contains only:

- nullable `Brand.branchId` column
- three non-unique indexes listed above
- foreign key from `Brand.branchId` to `Branch.id`

The migration must contain no `UPDATE`, `INSERT`, `DELETE`, `MERGE`, `DROP`, `TRUNCATE`, backfill, inference, copy, trigger, function, table rebuild, unique-constraint replacement, or data normalization.

Do not alter or drop the existing unique constraint/index on `Brand.normalizedName`.
